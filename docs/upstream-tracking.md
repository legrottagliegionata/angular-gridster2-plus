## Bugs found by code review

Fixed on 2026-09-14, one commit per bug, each with a spec that fails on the previous code.

| Where                                      | Problem                                                                                                     |
| ------------------------------------------ | ----------------------------------------------------------------------------------------------------------- |
| `gridsterRenderer.updateItem`              | Right outer margin guarded by `outerMarginBottom !== null` instead of `outerMarginRight`                    |
| `gridsterRenderer.updateItem` (mobile)     | Constant condition `DirTypes.LTR ? 'margin-right' : 'margin-left'`: RTL items kept `margin-left`            |
| `gridsterPushResize.restoreItems`          | Restored `$item.row` instead of `rows`                                                                      |
| `gridsterCompact.checkCompactItem`         | No `compactRight` / `compactRight&Up` preview; movements now come from one table shared with `checkCompact` |
| `gridster.addItem` / `autoPositionItem`    | Warnings printed `undefined` (the input signal instead of the item) and `/n`                                |
| `gridster.calculateLayout` (`setGridSize`) | Grid size ignored `outerMarginLeft/Right/Top/Bottom`                                                        |
| `gridster.setGridDimensions`               | `verticalFixed` rows shrank while dragging (#1003 only covered `scrollVertical`)                            |
| `gridsterScroll.ts`                        | `window` read at module load, breaking server-side rendering (#548)                                         |
| `gridsterEmptyCell.emptyCellMouseDown`     | `instanceof TouchEvent` threw where `TouchEvent` is undefined                                               |
| `gridsterItem.bringToFront/sendToBack`     | `zIndex` did not update until the next drag or resize                                                       |

Still open:

- `gridster.checkIfMobile` reads the global `document` when `useBodyForBreakpoint` is set, which fails during server-side rendering with that option.
- Changing `useTransformPositioning` at runtime leaves the previous positioning styles on the items (`setCellPosition` never clears `transform` or `top`/`left`), so they end up offset twice.

Checked and not a bug: #505 (the extra space comes from decimal `rows`/`y` values).

Push and swap issues checked on real components and not reproduced: #752 and #779 (same case as #941), #368 (resize with an item in column 0), #281 and #363 (push API after growing an item), #543 (`fromEast` pushes west and `fromWest` east, as documented), #753 (`disablePushOnDrag` stops pushes during swaps), #558 (the top items are pushed sideways and down), #892 (swaps follow the pointer, nothing swaps without moving it). By design: #882 and #893, a swap needs both items to fit at the other one's offset.

Resize and scrollbar issues checked in the demo and not reproduced: #371 (no growth with `setGridSize` and any outer margin, fixed by #989).

Drag and resize issues checked and not reproduced: #727 (`GridsterResizable.dragStart` already refuses to start while a drag is in progress, now covered by a spec), #359 (resizing from the top-left corner at the size limit leaves the item where it is), #784 (holding a resize against the grid edge no longer shrinks the item on its own, fixed by #919), #691 (no repro from the reporter, and nothing to see here). Still to check in the browser: #358 (resize with a margin of 0 to 4 against the grid edge).

Layout and options issues checked in the demo (1280×800 viewport) and not reproduced: #513 (one `emptyCellDropCallback` per drop, also on a child element; the handler stops propagation), #402 (a one-column `verticalFixed` grid has no horizontal overflow), #904 (the mobile layout scrolls since `flex-shrink: 0`, #1002), #777 (`addEmptyRowsCount` adds the rows), #606 (switching dashboards with compaction leaves the previous items untouched), #949 (the bottom outer margin after scrolling, fixed by the scroll spacer). Documented, not bugs: #525 (`gridSizeChangedCallback` follows rows and columns, not pixels), #616 (blurry text with `translate3d`, FAQ entry with `useTransformPositioning: false`).

Hidden or nested container issues checked in the demo (Browser pane visible: with it hidden the page renders in fits and starts and `ResizeObserver` notifications are unreliable) and not reproduced: #590, #594, #575 and #649 — a grid laid out inside a hidden panel measures 0 and its items come out wrong, and the `ResizeObserver` of #1009 lays it out correctly as soon as the panel is shown (`check(client=1066, curWidth=0)=true` → `onResize` → `calculateLayout`, columns back from -2 to 176 px); with `disableWindowResize: true` it stays wrong until `api.resize()`, as the FAQ says. #486 is fixed by the `setGridSize` change in #11. Documented, not bugs: #624 and #598 (`curColWidth`/`curRowHeight` are still 0 in `initCallback`, which runs before the first layout, and are set in `itemInitCallback`), #557 (two grids must not share the same item objects: the grid writes the positions into them).

## Notes for browser checks

`gridster-item` has `transition: .3s` on every property: disable transitions before measuring layout from scripts, otherwise sizes and even `flex-shrink` are read mid-animation.

## Lint

`ng lint angular-gridster2` is red on upstream master (checked 2026-09-14): 36 problems, mostly `consistent-type-definitions` on exported `type`s, `prefer-for-of`, `no-inferrable-types` and `any`/unused variables in `gridsterUtils.spec.ts`. The integration branch brings them down to 32 (upstream #1006 removes the four redundant `: string` annotations in `gridsterPush.ts`) and adds none. Switching the public `type`s to `interface` is an API-visible change to plan separately.
